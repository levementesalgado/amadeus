### 2. SNN — Rede Neural Spiking (T3 Alternativo)

**Objetivo**: Substituir cascata T3 por dinâmica temporal de spikes.

**Arquitetura**:
```
Input: 30 neurônios (rate-coded morph features)
Hidden: 263 neurônios (7×classe + 256×T3 keys)
Output: N neurônios (1 por lex_id)
LIF: tau=5.0, threshold=1.0, refrac=2, dt=1.0, tsteps=16
```

**Treinamento**: Pesos extraídos das tabelas T3 (coocorrência, sem learning online).

**Teste 1 — Vocab Pequeno (1 lex_id)**:
```
SNN top-1: 100% (match perfeito com cascade)
Cascade:   100%
```

**Teste 2 — Vocab Médio (3000 lex_ids)**:
```
Cascade top-1: 100%
SNN top-1:      23.3% (7/30)
SNN top-3:      40.0% (12/30)
SNN top-5:      40.0% (12/30)
```

**Teste 3 — Vocab Real (2250 lex_ids, dados diversificados)**:
```
Cascade top-1: 100%
SNN top-1:      30.0% (6/20)
SNN top-3:      50.0% (10/20)
```

**Performance**:
| Pipeline | Throughput | Speedup |
|----------|------------|---------|
| Cascade | 114.433 tok/s | 1.00x |
| SNN | 12.348 tok/s | 0.11x |

### 3. Pipeline Híbrido (LLM + Amadeus)

**Objetivo**: Mapear embeddings de LLMs comerciais para GRAPH 32-bit.

**Compressor**:
```
Input: embedding F32[4096] (Llama/Qwen/Phi)
Algoritmo: Random Indexing sparse (sqrt(dim) ≈ 64 projeções)
Output: GRAPH u32 (32 bits)
```

**Interpolação**:
```rust
interpolate_graphs(legacy_graph, llm_graph, weight=0.6)
// weight > 0.5 → favorece semântica LLM
// weight < 0.5 → favorece corpus treinado
```

**Resultado (1500 lex_ids, dados sintéticos)**:
| Métrica | Só legado | Híbrido (LLM+legado) |
|---------|-----------|----------------------|
| SNN top-1 | 23.3% | **30.0%** |
| SNN top-3 | 40.0% | **50.0%** |
| GGUF size | ~390 KB | ~6.2 MB |
| GGUF roundtrip | ✅ | ✅ |

**Latência estimada (T410, mmap)**:
| Componente | Latência |
|------------|----------|
| mmap grammar | ~0 (lazy) |
| mmap LLM embeddings | ~0 (lazy) |
| GRAPH interpolation | <1 ms |
| HyperCube lookup | <1 ms |
| SNN inference | ~10 ms |
| **Total por token** | **~12 ms** |

### 9. Análise

**Pontos positivos**:
- Texto mais coerente (sementes completas funcionam)
- SNN gera texto mais conciso (menos repetição)
- GRAPH embeddings permitem modulação semântica
- Vocabulário rico (650 entradas vs 37 antes)

**Problemas**:
- "música" e "país" aparecem muito (fallback do unigram)
- VERBO e ADJ nunca gerados (classes sub-representadas)
- SNN 4x mais lenta que cascade
- Muitos artigos da Wikipedia retornaram 0 bytes

### 10. Sessão 2: Otimizações e STDP

**Mudanças**:
1. Unigram: log-frequency para reduzir domínio de palavras frequentes
2. Compiler: classes morfológicas mais diversificadas
3. Corpus: +92 artigos narrativos (278 total)
4. SNN: STDP (Spike-Timing-Dependent Plasticity) implementado
5. SNN: Otimização SIMD-friendly (chunk de 4)

**Resultados**:
| Métrica | Antes | Depois |
|---------|-------|--------|
| Corpus | 186 artigos | 278 artigos |
| Tokens | 238K | 260K |
| Léxico | 650 | 653 |
| T2 | 4.445 | 4.536 |
| GRAPH | 26.937 | 30.053 |
| Repetição Cascade | 9.6% | 10.0% |
| Repetição SNN | 4.5% | 3.3% |
| Performance Cascade | 247 tok/s | 192 tok/s |
| Performance SNN | 64 tok/s | 49 tok/s |

**Análise**:
- SNN gera texto mais conciso (3.3% repetição vs 10.0%)
- Unigram log-frequency reduziu ligeiramente repetição
- Performance similar (SIMD não ajudou muito - branching é o gargalo)
- VERBO e ADJ ainda sub-representados

**Próximos passos**:
1. Corpus narrativo maior (histórias, conversas)
2. Balanced sampling no treinamento
3. Matrizes SNN achatadas para cache locality
4. Treinamento com STDP iterativo
